# Licensing and project identity

## Code license

WEFT 2.0 uses the Apache License 2.0.

Apache-2.0 allows use, modification, distribution, sublicensing, and commercial
use. It also contains an explicit patent-license grant from contributors.

The license grants rights to use and redistribute the work; it does not
transfer the original copyright to downstream users. Public copyright
attribution can use a project handle. A real name or identity-card number is
not required in the repository.

It does **not** prevent a downstream user from incorporating the code into a
closed-source product. A project that needs network copyleft must choose a
different license.

Earlier WEFT releases, including 0.2.0, distributed the Goal Compiler and Trust
Boundary under MIT. Changing the current repository to Apache-2.0 does not
revoke those earlier grants. New copies distributed from this 2.0 repository
are governed by the terms shipped with this version.

## Trademark

Apache-2.0 does not grant trademark rights. The WEFT name, logo, official
release identity, and compatibility claims remain separate project assets.

See [../TRADEMARKS.md](../TRADEMARKS.md).

Owner-side copyright, trademark, patent, registration, and future
commercial-licensing actions are tracked outside this public repository.

The public release does not transfer copyright ownership. It also does not
promise that every future WEFT component, runtime, service, or commercial
edition will use the same license.

## Provenance

Licensing identifies the rights attached to an artifact. Provenance identifies
where, when, and how the artifact was produced.

Public releases should use signed artifacts and verifiable build provenance.
Signing does not prevent copying; it makes impersonation and tampering easier to
detect.

This document records a project policy. Copyright, patent, trademark, consumer,
and contract questions are jurisdiction-specific and require professional legal
review before a public release or commercial offer.
